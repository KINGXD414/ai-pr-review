# ADR-001: 差异化方向选择 — 人格化 Reviewer + Self-Critique + 多次投票

## Context

在 72 小时实训营中，AI PR Review 工具需要找到差异化卖点。市场上已有成熟的 GitHub Action 集成（如 Codacy、SonarCloud）和 VSCode 插件（如 Codeium、GitHub Copilot），这些产品团队大、功能完善。我们在时间、人力和资源上都处于劣势，正面竞争无法胜出。

可选方向：
1. **GitHub Action** — 自动触发审查，与已有产品高度同质
2. **VSCode 插件** — 侧边栏展示结果，开发体验好但实现成本高（TypeScript + WebView + VSIX 打包）
3. **CLI 工具 + 差异化功能** — 聚焦审查质量本身，通过创新功能打出差异化

## Decision

选择 **CLI 工具 + 三招差异化功能**，不做 GitHub Action 或 VSCode 插件：

### 1. 人格化 Reviewer（--persona）

提供四种审查人格：
- `linus`：Linus Torvalds 风格，直言不讳，适合需要严厉审查的场景
- `mentor`：导师风格，耐心解释原因，适合新手代码审查
- `devil`：魔鬼代言人，故意挑刺，挖掘潜在风险
- `zen`：禅意风格，关注架构和设计，少纠结细节

**差异化价值：** 现有工具输出千篇一律的建议，人格化让审查有"对话感"，Demo 展示时节目效果强。

### 2. Self-Critique 反思链（--self-critique）

让 AI 先输出初版审查意见，再自动对初版进行反思和修正：
- 过滤误报：初版标记为 error 的问题，反思后可能降级为 warn
- 补充遗漏：初版未覆盖的风险点，反思后补充
- 增强建议：初版建议过于笼统时，反思后给出更具体的修复方案

**差异化价值：** 单次 LLM 输出存在幻觉和遗漏，反思链显著提升审查可靠性，具有学术深度。

### 3. 多次投票置信度（--consensus N）

运行 N 次独立审查，对每条 RuleHit 进行投票，只保留出现频率 ≥ 阈值的命中：
- N=1：普通模式，无投票
- N=3：至少 2/3 同意才保留
- N=5：至少 3/5 同意才保留

**差异化价值：** LLM 输出的随机性是工程痛点，投票机制将审查从"一次赌博"变为"多次验证"，置信度可量化。

## Consequences

### 正面
- **72小时内可交付**：三招功能都是 prompt engineering + CLI 参数，无需新框架
- **Demo 效果强**：`--persona linus` 喷人风格天然有传播性
- **学术深度**：反思链和投票机制有论文级创新点，评委加分
- **聚焦核心**：不分散精力做前端/集成，审查质量本身过硬

### 负面
- **缺少 GUI**：CLI 工具直观性不如 VSCode 插件，需靠 Demo 视频弥补
- **缺少自动化**：不集成 GitHub Action，无法 PR 提交自动触发
- **人格化可能失控**：linus 模式可能输出不当内容，需 prompt 边界约束

### 缓解措施
- Demo 视频重点展示 CLI 输出的结构化结果，降低 GUI 缺失的感知
- 未来扩展中明确规划 GitHub App 集成路径
- linus 人格 prompt 内置边界约束，禁止人身攻击和不当语言
