# ADR-001: 差异化方向选择 — 人格化审查者 + Self-Critique + 多次投票

## Context

现有产品（Codacy/SonarCloud/Copilot）功能完善但同质化严重，输出风格固定、缺乏多视角验证机制；72 小时窗口里的差异化机会不在做更大的平台，而在审查质量本身的工程化创新。

可选方向：
1. GitHub Action — 自动触发审查，与已有产品高度同质
2. VSCode 插件 — 侧边栏展示结果，开发体验好但实现成本高（TypeScript + WebView + VSIX 打包）
3. CLI 工具 + 差异化功能 — 聚焦审查质量本身，通过工程化创新打出差异化

### Alternatives Considered

- 不做 GitHub App：需 OAuth + Webhook + 服务器部署，72小时内无法稳定交付，且与 Codacy/SonarCloud 功能重叠
- 不做 IDE 插件：TypeScript + VSIX 打包链路长，调试成本高，且审查结果在 PR 页面展示更自然
- 不做 LangChain Agent 化：引入框架依赖增加复杂度，当前 prompt engineering 已足够实现目标功能

## Decision

选择 CLI 工具 + 三招差异化功能，不做 GitHub Action 或 VSCode 插件：

### 1. 人格化审查者（多视角审查）

提供多种审查人格，适配不同审查场景：
- 严厉直接、对事不对人 — 适合资深团队需要高效审查
- 导师风格 — 耐心解释原因，适合新手代码审查
- 对抗式审查 — 专挑 edge case、空指针、并发、整数溢出
- 鼓励式沟通 — 先肯定再具体建议

另含 default 兜底，不指定人格时使用均衡资深模式。

现有工具输出千篇一律的建议，多视角让同一份代码从不同角度审视能发现不同风险。

### 2. Self-Critique 反思链（两阶段自我修正）

让 AI 先输出初版审查意见，再自动对初版进行反思和修正：
- 过滤误报：初版标记为 error 的问题，反思后可能降级为 warn
- 补充遗漏：初版未覆盖的风险点，反思后补充
- 增强建议：初版建议过于笼统时，反思后给出更具体的修复方案

单次 LLM 输出存在幻觉和遗漏，两阶段修正显著提升审查可靠性，具备可量化指标（反思修正率）。

### 3. 多次投票置信度（多采样共识过滤）

运行多次独立审查，对每条命中进行投票，只保留出现频率 ≥ 阈值的结果：
- 普通模式：无投票，单次输出
- 多采样模式：至少 2/3 同意才保留
- 高置信模式：至少 3/5 同意才保留

LLM 输出的随机性是工程痛点，共识过滤把审查从"一次赌博"变为"多次验证"，置信度可量化。

## Consequences

### 正面
- 72小时内可交付：三招功能都是 prompt engineering，无需新框架
- Demo 效果强：严厉模式对代码直击痛点
- 工程深度：反思修正率和置信度阈值具备可量化指标
- 聚焦核心：不分散精力做平台集成，审查质量本身过硬

### 负面
- 缺少 GUI：CLI 工具直观性不如 IDE 插件，需靠 Demo 视频弥补
- 缺少自动化：不集成 GitHub Action，无法 PR 提交自动触发
- 强语气人格的输出语气需要持续校准：已在 prompt 内置"对事不对人"边界约束，禁止人身攻击

### 缓解措施
- Demo 视频重点展示 CLI 输出的结构化结果，降低 GUI 缺失的感知
- 未来扩展中明确规划 GitHub App 集成路径
- 持续迭代人格 prompt，确保输出边界可控
